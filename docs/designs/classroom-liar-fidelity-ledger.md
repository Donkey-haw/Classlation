# 클래스 라이어 학생 디자인 감사 기록

최종 검증일: 2026-08-20
검증 크기: 교사 1440×1024, 학생 390×844

## 현재 디자인 판단

초기 시안의 흰 배경·남색 글자·코발트 블루 중심 디자인은 유지한다. 실제 수업 관찰을 반영해 학생 화면의 목적은 “계속 조작하는 게임 화면”이 아니라 “필요한 순간만 정보를 전달하고 대면 대화로 돌려보내는 화면”으로 수정했다.

## 감사 결과와 반영

| 비교 항목 | 감사 전 문제 | 현재 구현 | 판정 |
|---|---|---|---|
| 팀 배정 | 큰 팀 번호만 있어 다른 팀과 시각적 구분이 약함 | 팀마다 색·기호·별칭·번호를 함께 표시 | 개선 |
| 역할 공개 | 정보는 명확하지만 비밀 역할을 확인하는 긴장감이 약함 | `나만 보는 비밀 카드`, 역할별 색, 0.42초 공개 전환 추가 | 개선 |
| 대면 대화 | `팀 투표 시작` 파란 버튼이 기기 내려놓기보다 강하게 보임 | 대화 종료 질문 아래 외곽선 보조 버튼으로 낮춤 | 개선 |
| 결과 기호 | 자동 판정이 아닌 공개 화면에도 체크가 있어 성공으로 오해 가능 | 중립 상태는 `정답`·`정답 공개!`로 표시 | 개선 |
| 결과 정보 | 지목된 사람과 라이어가 같을 때 이름이 중복됨 | 같은 사람은 한 번만 표시하고 실제 주제어를 강조 | 개선 |
| 작은 글자 | 팀원·대화 규칙·안내 일부가 10~12px | 학생 핵심 안내 12px 이상, 대화 규칙 13px | 개선 |
| 제품 이름 | `교실 라이어`와 `클래스 라이어`가 혼용됨 | 학생 입장 화면을 `클래스 라이어`로 통일 | 개선 |
| 팀 편집 | 자동 배정 결과를 수업 상황에 맞게 바꿀 수 없음 | 기존 카드 문법 안에서 학생별 팀 선택, 팀 추가·제거, 다시 섞기 제공 | 개선 |
| 재입장 | 저장 정보가 사라지면 마감된 방에서 막힘 | 별도 재입장 요청 카드와 교사의 기존 참가자 승인 제공 | 개선 |
| 다음 라운드 | 새 팀을 원해도 같은 팀으로만 진행 | `새 팀으로 이동하세요` 제목과 기존 팀 카드 편집 화면을 재사용 | 개선 |

## 유지한 원칙

- 그림자와 그라데이션 없이 얇은 경계와 높은 글자 대비를 사용한다.
- 역할 외에는 불필요한 애니메이션을 두지 않는다.
- 팀 정체성은 색뿐 아니라 기호·별칭·번호를 함께 사용한다.
- 학생별 발언·질문 완료 버튼을 다시 추가하지 않는다.
- 대화 중 화면보다 학생 얼굴과 목소리가 중심이 되게 한다.

## 검증 결과

- 교사 1개와 학생 5개 브라우저 컨텍스트의 전체 라운드 통과
- 교사 1개와 학생 10개 컨텍스트에서 10명 큰 팀, 3·3·4명 편집, 승인 재입장, 라운드 재편성 통과
- 학생 390×844에서 팀 배정, 팀원 역할, 라이어 역할, 대면 대화, 결과 화면 확인
- 역할 공개 애니메이션 종료 뒤 텍스트와 버튼이 선명하게 표시됨
- 같은 브라우저 새 탭 자동 복구와 새 저장소의 교사 승인 복구 확인
- 브라우저 콘솔 오류 0건
- `window.render_game_to_text()`가 화면 단계와 일치

## 남은 현장 검증

시각적으로 더 화려한 요소를 추가하기 전에 다음 실제 수업에서 아래를 확인한다.

1. 팀 색·기호·별칭이 자리 이동을 실제로 빠르게 만드는가?
2. 역할 카드가 재미를 높이면서도 다른 학생에게 노출되지 않는가?
3. 외곽선형 투표 버튼을 대화 종료 후 쉽게 찾는가?
4. 학생이 기기를 내려놓고 전원 발화에 참여하는가?
5. 실제 iPad 브라우저 종료 뒤 재입장 요청과 승인이 혼란 없이 되는가?
6. 새 팀 배정 뒤 이동 시간이 수업 흐름을 방해하지 않는가?
