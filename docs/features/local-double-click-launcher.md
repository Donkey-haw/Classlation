# 로컬 더블클릭 런처

## Why

현재 클래스 라이어를 실행하려면 터미널에서 폴더 이동, 설치, 빌드, 서버 시작 명령을 알아야 한다. 게임이 늘어나기 전에 비개발자인 교사가 Finder에서 시작과 종료를 직접 할 수 있는 가장 작은 실행 장치가 필요하다.

이 런처는 여러 게임을 하나의 규격으로 합치는 허브가 아니다. 지금은 클래스 라이어 한 게임을 쉽게 실행하고, 두 번째 게임이 실제로 생겼을 때 선택 화면으로 확장할 수 있는 출발점만 만든다.

## User flow

1. 교사가 프로젝트 최상단의 `Classlation 시작.command`를 더블클릭한다.
2. 런처가 Node.js와 pnpm, 첫 설치 여부, 최신 빌드를 자동으로 확인한다.
3. 서버가 준비되면 기본 브라우저에서 교사 화면이 자동으로 열린다.
4. 터미널 창에는 `실행 중`과 종료 방법만 크게 표시된다.
5. 교사는 터미널에서 `Control + C`를 누르거나 `Classlation 종료.command`를 더블클릭해 서버를 종료한다.
6. 이미 실행 중이면 새 서버를 중복 실행하지 않고 기존 교사 화면만 다시 연다.

## Completion criteria

- Finder에서 시작 파일을 더블클릭하면 별도의 명령 입력 없이 클래스 라이어가 열린다.
- 첫 실행에 의존성이 없으면 자동 설치하고, 항상 production 화면을 최신 코드로 빌드한 뒤 실행한다.
- `http://localhost:4173/api/health`가 클래스 라이어 서버임을 확인한 뒤에만 브라우저를 연다.
- 4173 포트를 다른 프로그램이 사용 중이면 그 프로그램을 종료하지 않고 이해하기 쉬운 오류를 표시한다.
- 시작 파일을 두 번 실행해도 클래스 라이어 서버는 하나만 유지된다.
- 종료 파일은 런처가 시작한 클래스 라이어 서버만 종료하며, 다른 프로세스는 종료하지 않는다.
- Node.js 또는 pnpm이 없으면 필요한 항목과 현재 프로젝트 경로를 한국어로 안내한다.

## Not included

- 여러 게임을 선택하거나 전환하는 허브 화면
- 공통 방·팀·학생 세션
- macOS `.app` 패키지, 서명, 공증, 자동 업데이트
- Node.js와 pnpm 자체를 설치하는 시스템 설치 도구
- 다른 교사에게 배포할 독립 설치 프로그램

## Data and privacy

- 런처는 학생 데이터나 게임 내용을 저장하지 않는다.
- 실행 중인 서버의 프로세스 번호를 프로젝트의 임시 PID 파일에 기록하고 종료 시 삭제한다.
- 빌드·실행 오류는 실행 중인 터미널에만 표시하며 외부로 전송하지 않는다.

## Verification

- `zsh -n 'Classlation 시작.command'`와 `zsh -n 'Classlation 종료.command'` 구문 검사 통과
- 시작 파일 직접 실행 후 `http://localhost:4173/api/health`에서 `{"ok":true,"app":"classroom-liar"}` 확인
- production 교사 HTML 제공과 PID 파일·실제 4173 listener의 프로세스 번호 일치 확인
- 실행 중 시작 파일을 다시 실행했을 때 새 서버 없이 기존 서버를 감지하는 흐름 통과
- 종료 파일 실행 후 health endpoint 중단과 PID 파일 삭제 확인
- 4173 포트에 임시 다른 서버를 실행한 상태에서 시작·종료 파일이 해당 서버를 종료하지 않는 안전성 확인
- 기존 게임의 TypeScript 검사, 단위·통합 테스트 14개, production build 통과
- Finder의 실제 더블클릭은 `.command` 실행 권한과 동일 셸 경로를 사용하지만, 자동 검증에서는 브라우저가 불필요하게 열리지 않도록 환경 변수로 `open` 명령만 생략함
