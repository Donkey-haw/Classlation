# 클래스 라이어 — 재입장과 유연한 팀 운영

## Why

두 번째 실제 수업에서 브라우저를 벗어난 학생이 기존 재접속 정보를 잃으면 마감된 방에 돌아오지 못했다. 또한 교사가 자동 배정 결과를 수업 상황에 맞게 조정하고, 더 큰 팀이나 라운드별 새 팀을 선택하고 싶다는 요구가 확인됐다.

## User flow

### 재입장

1. 같은 기기의 학생은 브라우저를 닫거나 다른 페이지로 이동해도 저장된 임시 연결 정보로 자동 복귀한다.
2. 자동 복귀 정보가 없으면 학생이 기존에 사용한 이름으로 `재입장 요청`을 보낸다.
3. 교사는 연결이 끊긴 기존 참가자 중 누구인지 선택해 승인하거나 요청을 거절한다.
4. 승인하면 새 연결 정보가 발급되고 학생은 기존 팀·역할·진행 단계로 돌아간다. 이전 연결 정보는 더 이상 사용할 수 없다.

### 팀 준비와 편집

1. 교사는 방을 만들 때 권장 팀 인원을 3~32명에서 정한다.
2. 입장을 마감하면 앱이 3명 미만 팀이 생기지 않도록 균등하게 자동 배정한다.
3. 역할 공개 전 교사는 팀 추가, 빈 팀 제거, 자동 다시 섞기, 학생별 팀 이동을 할 수 있다.
4. 모든 팀에 3명 이상 있어야 라운드를 시작할 수 있다.

### 라운드별 팀 선택

1. 방 생성 시 `팀 유지`가 기본값이다.
2. `라운드마다 새 팀`을 선택하면 다음 라운드 전에 팀을 다시 섞고 자리 이동 화면으로 돌아간다.
3. 교사는 새 팀도 필요하면 수정한 뒤 다음 라운드를 시작한다.

## Completion criteria

- 새 탭이나 브라우저 재실행 뒤 같은 기기에서 기존 학생이 자동으로 복귀한다.
- 저장 정보가 없는 학생이 마감된 방에서 재입장을 요청하고, 교사 승인 전에는 게임 정보를 받지 못한다.
- 교사가 연결이 끊긴 기존 참가자에게 요청을 승인하면 같은 player ID, 팀, 역할, 주제어, 단계가 복구되고 새 임시 토큰이 발급된다.
- 연결된 학생이나 존재하지 않는 참가자에게는 재입장을 승인할 수 없다.
- 교사는 역할 공개 전에 팀을 추가하고, 빈 팀을 제거하고, 학생을 다른 팀으로 이동하고, 전체 팀을 다시 섞을 수 있다.
- 팀원이 3명 미만인 팀이 있으면 라운드를 시작할 수 없으며 화면에서 이유를 알 수 있다.
- 3~32명의 참가자를 권장 인원 3~32명으로 자동 배정할 수 있고, 한 팀에 6명보다 많이 배정할 수 있다.
- `라운드마다 새 팀`에서는 결과 공개 후 다음 라운드가 즉시 시작되지 않고 새 팀 확인·자리 이동 단계를 거친다.
- `팀 유지`에서는 기존처럼 바로 다음 라운드 역할 확인으로 넘어간다.

## Not included

- 학생 계정이나 비밀번호
- 서버 재시작 뒤 방 복원
- 학생이 스스로 기존 참가자 이름을 선택하는 화면
- 32명 초과 학급
- 라운드별 팀을 반드시 완전히 다르게 만드는 수학적 보장
- 실명 강제나 실명 검증. 실명 사용은 교사의 수업 안내로 처리한다.

## Data and privacy

- 학생 기기에는 방 코드, 무작위 player ID, 재접속용 임시 토큰만 로컬 저장한다.
- 재입장 요청 이름과 요청 ID는 교사의 MacBook 메모리에만 두고 승인·거절·연결 종료 시 삭제한다.
- 외부 서버 전송과 영구 저장은 없다.
- 게임 종료 시 기존과 같이 방, 참가자, 역할, 투표, 재입장 요청을 모두 삭제한다.

## Verification

- 도메인·스토어·스키마 테스트 20개와 타입 검사, 프로덕션 빌드를 통과했다.
- 교사 1개와 학생 10개 브라우저 컨텍스트에서 10명 한 팀, 3·3·4명 수동 편집, 같은 브라우저 자동 복귀, 새 저장소에서 승인 재입장, 2라운드 새 팀 배정을 검증했다.
- 기존 교사 1개·학생 5개 전체 게임 흐름도 다시 통과했다.
- 교사 1440×1024와 학생 390×844 화면을 직접 확인했고 두 E2E 모두 콘솔 오류 0건이었다.
- 실제 iPad가 브라우저 앱을 완전히 종료한 뒤 복귀하는 동작은 다음 수업에서 추가 확인한다.
